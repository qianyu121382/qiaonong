## 2. URL、页面区块与锚点

- 首页：`/`
- 栏目页：`/index.php?s=index/category/index&id={栏目ID}`
- 产品详情页：`/index.php?s=index/show/index&id={产品ID}`
- 搜索：页面顶部搜索图标打开搜索层，搜索框通过表单发起查询；它不是页面内内容锚点。
- 未发现以 `#...` 表示的页面内锚点导航。
- 一级导航和二级栏目几乎都指向独立的栏目 URL；旧站把很多“单个产品名称”也建成了栏目页，再从栏目页进入真正的产品详情 URL，信息层级有重复。
- 品牌介绍至少存在 `id=1` 与 `id=46` 两个栏目 URL，标题相同，属于疑似重复内容。
- 首页历史快照中曾出现一个文字为空、`id` 也为空的一级导航链接；在稍后的栏目快照中该位置显示为“医美产品”（`id=60`），说明导航配置曾不完整或缓存版本不一致。

## 5. 桌面端与手机端差异

可确认情况：

- 页面声明了移动端 viewport，但主要 CSS 大量使用 `1200px`、`1280px`、`1320px`、`1360px`、`1400px` 固定宽度。
- 导航容器设置了 `min-width: 1200px`；产品列表采用固定宽度三列；详情页使用固定宽度的缩略图、622px 主图和右侧信息栏。
- 样式表只发现一处 `min-width: 1024px` 的悬停增强规则，没有发现完整的手机断点布局。

据此可判断旧站虽声明支持 `pc,wap`，但没有可靠的移动端重排方案。手机端很可能出现横向溢出、文字/图片过小、依赖 hover 的交互不可用等问题。由于历史快照无法完整执行并对比真实手机浏览器，这部分属于代码证据支持的推断，仍应在实时站恢复或拿到原始素材后复核；新版不建议照搬。

## 6. 迁移规模初估

- 独立栏目 URL：历史索引中至少 33 个分类/内容页。
- 产品详情：栏目链接中可见的产品 ID 延伸至 75；按各栏目独有详情入口初步估算约 40 个产品条目，但历史快照完整保存的详情页远少于此数，准确数量需从旧后台导出或由用户提供清单。
- 首页内容图片：HTML 中约 21 个图片引用，包含主视觉、产品/系列入口和品牌区图片。
- 栏目页：每页通常约 10～16 个图片引用，其中大量是公共导航图片；实际产品列表一般为 1～6 个产品卡片。
- 产品详情：至少需要封面/主图、缩略图、可能的悬停图与详情长图；按约 40 个产品估算，产品相关图片大概率在 80～200 张量级，需去重后确认。
- 文字量：品牌介绍只有一段简短文案；联系我们仅一行电话；政策页为空。主要文字迁移量集中在产品名称、简介、规格和详情说明。

该规模仅用于判断工作量，不能作为最终迁移数量。迁移前应取得原始高清图片和可编辑文字，避免从历史快照直接下载低清、缺失或未经确认的素材。

## 7. 异常、失效内容与不建议照搬项

- 实时站状态不稳定：2026-08-09 复核时 HTTP 返回 `200 OK`，但 HTTPS 使用的证书不受信任且证书域名不匹配，不能视为正常的安全访问状态。
- 搜索引擎几乎没有该域名的有效收录。
- 2025-06 首页快照的“医美产品”导航位置为空链接；后续快照才出现 `id=60`。
- 品牌介绍存在两个疑似重复 URL（`id=1`、`id=46`）。
- 使用政策、隐私条款、Cookies 政策正文为空，不能原样迁移；若新版收集用户数据，需要重新拟定真实有效的政策内容。
- 联系我们只有电话号码，没有公司名称、地址、邮箱、地图或服务时间等完整企业信息。
- 首页快照出现“侵权告知函”标题以及“前往购买”“我已购买”等与建站模板授权/缓存相关的链接，其中“前往购买”指向建站系统站点，明显不属于品牌内容，不应迁移。
- 页面链接采用冗长的 PHP 查询参数和数字 ID；新版应设计稳定、可读的 URL，并为确需保留的旧 URL 准备重定向表。
- 产品分类层级重复：多个单品既是二级栏目又有产品详情页，增加导航和后台维护成本，不建议机械照搬。
- 页面大量依赖固定像素宽度、背景图和 hover 效果，响应式与无障碍表现较弱。
- 图片普遍缺少有效 `alt` 文本，标题层级也很少使用语义化标题标签，不利于 SEO 和可访问性。
- 备案号、联系方式、社交账号、二维码、医美类产品表述及产品功效文案均需由用户核验后才能迁移；不能把历史快照视作当前有效或合规资料。
