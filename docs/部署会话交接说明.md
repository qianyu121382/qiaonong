## 1. 部署目标

当前目标是把巧侬第一版部署到现有 Ubuntu 服务器供用户预览和验收，不代表所有企业资料、政策与 SEO 已最终定稿。

技术组成：

- 公开前端：Vue + Vite，生产构建输出 `frontend/dist/`，由 Nginx 静态托管。
- 管理前端：Vue + Vite，生产构建输出 `admin-frontend/dist/`，挂载在 `/manage/`。
- 后端：Django 5.2 + Django REST Framework + Gunicorn。
- 数据库：PostgreSQL 16 目标基线。
- 媒体：Django `MEDIA_ROOT`，生产目标为 `/srv/qiaonong/media/`。
- 不采用 Wagtail；管理员使用项目自带管理前端，Django Admin 只作开发与应急入口。

## 3. 项目隔离红线

服务器同时承载婵泉，但巧侬必须拥有独立的：

```text
/srv/qiaonong/app
/srv/qiaonong/venv
/srv/qiaonong/media
/srv/qiaonong/static
/srv/qiaonong/logs
/srv/qiaonong/backups
/run/qiaonong/gunicorn.sock
qiaonong.service
qiaonong_prod 数据库
qiaonong_app 数据库角色
独立 backend/.env
独立 Nginx server 配置
独立管理员账号与备份
```

严禁读取、复制或复用婵泉的 `.env`、数据库、角色、媒体目录、管理员账号、Gunicorn socket、systemd 服务或备份。可以共用服务器上的 Nginx、PostgreSQL 服务进程和 Certbot，但业务资源必须隔离。

仓库和本文不得记录公网 IP、SSH 用户、私钥、数据库密码或生产密钥。部署会话应从它原有的安全上下文取得服务器权限；缺少权限时询问用户，不得到其他项目配置中寻找。

## 5. 推荐的首次预览部署流程

### 阶段 A：本地发布基线

1. 阅读上述文档并检查 `git status`、`git diff`，排除 `.idea/`、临时截图、`.env`、媒体和构建产物。
2. 执行：

   ```powershell
   cd E:\MyCode\Code\qiaonong\frontend
   npm run build

   cd E:\MyCode\Code\qiaonong\admin-frontend
   npm run build

   conda activate chanquan-django
   cd E:\MyCode\Code\qiaonong\backend
   python manage.py check
   python manage.py makemigrations --check --dry-run
   ```

3. 经用户授权后提交、推送，等待 GitHub Actions 前后端全部通过。
4. 记录将要部署的完整提交 SHA，不使用模糊的“最新代码”。

### 阶段 B：服务器只读盘点

先确认但不修改：

- Ubuntu、磁盘、内存、Swap、PostgreSQL、Nginx、Certbot 与 systemd 状态。
- `/srv/qiaonong/`、`qiaonong` Linux 用户、数据库/角色、service、socket 和 Nginx 站点是否已经存在。
- `zgqnht.com` 当前 DNS 指向和旧站承载位置。
- 80/443 端口现有 server block，确认不会覆盖婵泉域名配置。

若巧侬资源已经存在，修改前先备份巧侬数据库、媒体、环境配置和当前提交；不要备份到婵泉目录。

### 阶段 C：创建独立运行资源

按 `docs/服务器配置与部署约束.md` 和 `deploy/README.md` 创建独立用户、目录、Python 虚拟环境、PostgreSQL 数据库/角色及权限。生产 `.env` 由 `deploy/qiaonong.env.example` 创建并设为 `600`，所有密码与密钥只在服务器安全保存。

不要在首次验证 HTTPS 前盲目启用 HSTS。可先把 `DJANGO_SECURE_HSTS_SECONDS` 设为 `0` 验收，HTTPS 和域名完全确认后再设为模板值。

### 阶段 D：部署代码与构建

1. 在 `/srv/qiaonong/app` 拉取并检出已确认提交。
2. 在 `/srv/qiaonong/venv` 安装 `backend/requirements/prod.txt`。
3. 执行两个前端的 `npm ci && npm run build`；Node.js 只用于构建，不作为常驻服务。
4. 执行生产检查、迁移与静态文件收集：

   ```bash
   cd /srv/qiaonong/app/backend
   DJANGO_SETTINGS_MODULE=config.settings.production /srv/qiaonong/venv/bin/python manage.py check --deploy
   DJANGO_SETTINGS_MODULE=config.settings.production /srv/qiaonong/venv/bin/python manage.py migrate
   DJANGO_SETTINGS_MODULE=config.settings.production /srv/qiaonong/venv/bin/python manage.py collectstatic --noinput
   ```

### 阶段 E：初始化内容与传输媒体

推荐首次预览使用可重复的迁移命令创建公开数据：

```bash
cd /srv/qiaonong/app/backend
DJANGO_SETTINGS_MODULE=config.settings.production /srv/qiaonong/venv/bin/python manage.py import_legacy_catalog \
  --copy-images --publish-products --import-public-site
```

然后把本机 `backend/media/` 的内容安全同步到服务器 `/srv/qiaonong/media/`。传输前后统计文件数量和体积；使用不会误删服务器其他目录的方式，不允许把目标写成 `/srv/`、`/` 或婵泉媒体目录。首次同步不需要使用带 `--delete` 的命令。

迁移命令会导入旧站公开基础素材，但不会自动选择本地生成的 7 张新图。完整媒体传输后，需要在生产数据库把首页品牌图、品牌页图和 6 个一级分类横幅指向下列相对路径：

```text
content/generated/2026/08/brand-story-ai-v1.webp
content/generated/2026/08/series-skin-ai-v1.webp
content/generated/2026/08/series-eye-ai-v1.webp
content/generated/2026/08/series-aqua-ai-v1.webp
content/generated/2026/08/series-makeup-ai-v1.webp
content/generated/2026/08/series-salon-ai-v1.webp
content/generated/2026/08/series-medical-ai-v1.webp
```

优先通过巧侬管理后台设置这些字段；如首次部署必须使用 Django shell，应先打印旧值、只修改 `SiteSettings(pk=1)`、`ContentPage(slug='brand')` 和上述 6 个明确 slug，并在修改后再次打印核对。不要对未知记录做批量更新。

不要直接恢复或复制婵泉数据库。若部署会话考虑把本地巧侬数据库整体迁到生产，必须先向用户说明会包含哪些 Django 系统表，并使用 `--no-owner` 等方式避免带入本地数据库所有权；默认优先采用上面的迁移命令和明确字段设置。

最后创建全新的巧侬生产管理员，不复用本地或婵泉账号：

```bash
DJANGO_SETTINGS_MODULE=config.settings.production /srv/qiaonong/venv/bin/python manage.py createsuperuser
```

管理员密码不得写入仓库、日志或本文。

### 阶段 F：服务、Nginx 与域名

1. 安装并启动独立 `qiaonong.service`，检查 socket、`systemctl status` 和 `journalctl -u qiaonong`。
2. 从模板创建独立 Nginx 站点，先执行 `nginx -t`，不要覆盖其他域名 server block。
3. 在正式 DNS 或旧站切换前，优先使用本机 Hosts 映射或用户确认的预览域名验证。
4. `zgqnht.com` 与 `www.zgqnht.com` 的主域和 301 方向仍需用户确认。
5. 切换 DNS、替换旧站或签发正式证书属于外部可见变更，执行前必须得到用户明确确认。
6. HTTPS 验收通过后再开启安全 Cookie、HTTPS 跳转和最终 HSTS。

## 6. 部署验收清单


人工检查至少包括：

- `/`：6 张轮播约每 5 秒切换，有链接的横幅整张可点击。
- 首页产品系列：6 个标签可切换，主图、二级栏目与代表产品同步更新。
- `/brand`：显示无文字品牌氛围横幅，不重复旧站排版图。
- `/products/skin-care` 等 6 个一级分类：显示各自横向图片，不出现“浏览巧侬已经公开的产品资料”占位句。
- 任一二级分类：继承所属一级系列横幅并显示正确产品。
- 产品详情、搜索、旧 PHP URL 重定向。
- `/contact`：不显示“以下联系资料由巧侬管理员维护。”，电话与微信二维码可用。
- 页脚：高度紧凑，只有必要导航、电话和微信；二维码可展开。
- `/manage/`：独立管理员可登录、CSRF 正常，能读取但不误修改内容。
- `/api/health/`、分类 API、产品 API、站点设置 API。
- 桌面端与手机端无横向页面溢出，图片与字体无 404。
- Nginx 媒体和带哈希静态资源缓存正常。
- 婵泉站点、服务、数据库和媒体完全不受影响。

记录最终部署提交 SHA、数据库初始化方式、媒体文件数量/体积、服务状态和验收结果。
