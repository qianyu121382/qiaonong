# 巧侬第一版实现与部署前检查

> 历史说明：本文记录第一版上线前的实现基线与验收清单。第一版现已正式上线，当前状态请优先阅读 `docs/当前进度与下一步.md`；不要再把本文中的“部署前”措辞当作当前事实。

## 当前实现范围

第一版应用代码已覆盖已确认范围：

- 公开站：首页、品牌介绍、一级/二级产品分类、产品列表、产品详情、站内搜索、联系我们和政策页面。
- 响应式：首页、导航、分类列表、产品卡片、产品详情、联系页和页脚均包含手机布局，不再沿用旧站固定 1400px 宽度。
- 管理后台：独立登录、会话恢复、退出、产品分类、产品、产品图片、网站设置、内容页面和首页轮播图维护。
- 后端：Session + CSRF 管理认证、登录限流、公开只读 API、管理员写 API、图片校验、上下架与分类可见性规则。
- 迁移：从仓库内旧站公开归档导入分类、产品和图片；默认全部产品下架，政策及主体相关页面只创建待核验空壳。
- 兼容：旧产品和栏目 PHP URL 可根据迁移后的旧站 ID 返回永久重定向。

## 安全边界

- 管理登录、退出及所有写 API 使用 Django Session 与 CSRF，不使用 JWT。
- 登录接口限制为每来源每分钟 10 次尝试，错误响应不泄露账号是否存在。
- 只有启用且具有后台权限的巧侬管理员账号可以登录。
- 图片仅允许 JPG、PNG、WebP，单张不超过 10 MB，宽高不超过 8000 像素；Nginx 请求上限为 12 MB。
- 生产设置支持 HTTPS 跳转、安全 Cookie 和 HSTS，CI 使用生产设置执行 `check --deploy`。
- 巧侬的数据库、账号、环境变量、媒体、进程、socket、站点配置和备份均保持独立。

## 上线前曾要求用户确认

以下内容不能依据旧站自动决定：

1. 巧侬真实公司主体、地址、电话、邮箱、备案号和备案链接。
2. 最终 Logo、首页主视觉、品牌介绍、二维码和政策正文。
3. 哪些迁移产品允许公开，以及医美类和功效类表述是否合规、准确。
4. `zgqnht.com` 与 `www.zgqnht.com` 哪个作为主域名。
5. 旧 URL 是否全部保留重定向，还是只处理有访问价值的页面。

以上资料缺失时，系统只显示安全的待更新或未发布状态，不会采用旧站中婵泉的公司、地址、备案或账号信息。

## 首次部署验收主线

1. 创建巧侬独立管理员并登录 `/manage/`。
2. 填写网站设置及已核验内容页面。
3. 检查迁移分类和产品，上传或更换图片并上架一个测试产品。
4. 在公开站确认该产品出现在正确分类、搜索结果和详情页。
5. 下架测试产品，确认公开 API 和页面不再显示。
6. 分别在桌面端与手机端验收首页、导航、列表、详情、联系和政策页。
7. 验证 HTTPS、Cookie、上传、备份、恢复和旧 URL 重定向。

上述主线已在首次预览、正式域名切换和后续生产部署中执行。现行自动部署及运维规则见 `docs/CD方案与接入说明.md` 和 `deploy/README.md`。
