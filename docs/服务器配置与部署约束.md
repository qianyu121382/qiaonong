# 巧侬服务器配置与部署约束

## 1. 服务器背景

巧侬新站已部署在现有的阿里云轻量应用服务器上。该服务器同时承载婵泉项目，因此这里的“独立项目”是指代码、进程、数据和运维边界完全隔离，不要求当前必须购买第二台物理服务器。

当任一项目的访问量、存储量或运维需求明显增长时，应能够把巧侬完整迁移到另一台服务器，而不影响婵泉。

本仓库不得记录公网 IP、SSH 用户、私钥、数据库密码、生产环境变量或其他凭据。

## 2. 当前服务器配置

- 云厂商：阿里云
- 产品：轻量应用服务器
- 地域：中国内地节点，当前服务器位于北京地域
- 操作系统：Ubuntu 24.04 LTS，使用纯净系统镜像
- CPU：2 核
- 内存：4 GB
- 系统盘：50 GB SSD
- 公网地址：1 个独立 IPv4
- 公网带宽：购买页面标注最高 200 Mbps
- 流量：购买页面标注无固定流量或不限流量
- 管理方式：SSH 与命令行
- 不使用宝塔等服务器面板
- 当前已配置约 4 GB Swap，用于降低构建、升级或短时内存峰值导致进程被终止的风险

“200 Mbps”应理解为产品标注的峰值带宽，不是持续独享的固定 200 Mbps。对于两个中小型企业展示官网通常足够，但图片资源仍需压缩、缓存并持续观察实际流量。

## 3. 可共用的系统服务

初期同机部署时，以下系统级服务可以由婵泉和巧侬共用：

- Nginx：按域名将请求分发到不同项目
- PostgreSQL 服务进程：同一个数据库服务中创建完全独立的数据库和数据库角色
- Certbot：分别为不同域名申请和续期证书
- 操作系统、防火墙、时间同步和系统级监控

共用系统服务不代表共用业务配置或数据。

## 4. 巧侬必须独立的内容

巧侬必须拥有自己的：

- Git 仓库和部署目录
- Linux 运行用户或明确隔离的文件权限
- Python 虚拟环境
- Django/Gunicorn 服务及 systemd unit
- PostgreSQL 数据库和数据库角色
- `.env` 生产环境变量
- 上传媒体目录
- 静态文件目录
- 应用日志
- Nginx 站点配置
- 域名和 HTTPS 证书配置
- 数据库与媒体备份
- 管理员账号

禁止直接复用婵泉的数据库、环境变量、Gunicorn socket、媒体目录、管理员账号或备份文件。

## 5. 建议目录和服务命名

生产已经采用以下清晰、可迁移的结构：

```text
/srv/qiaonong/
├── app/          # Git 工作区
├── venv/         # Python 虚拟环境
├── media/        # 后台上传文件
├── static/       # Django collectstatic 产物
├── logs/         # 项目日志
└── backups/      # 巧侬独立备份
```

服务和资源命名：

```text
systemd:       qiaonong.service
Gunicorn:      /run/qiaonong/gunicorn.sock
数据库:        qiaonong_prod
数据库角色:    qiaonong_app
Nginx 配置:    qiaonong
```

这些资源已经创建并投入生产，实际状态仍以服务器只读检查和最近一次成功部署记录为准。

## 6. Nginx 与域名规划

Nginx 根据域名区分两个项目：

```text
chanquanyaoye.com  → 婵泉官网、婵泉 API、婵泉管理后台
zgqnht.com         → 巧侬官网、巧侬 API、巧侬管理后台
```

两个站点应使用独立的 Nginx `server` 配置。不得依靠路径前缀把巧侬挂在婵泉域名下。

巧侬已完成：

- 根域名和 `www` 的 DNS 解析
- 主域名选择及另一域名的 301 跳转
- Let's Encrypt 证书申请
- HTTP 到 HTTPS 跳转
- 管理后台登录、CSRF、Cookie 和媒体资源的 HTTPS 验收
- ICP 备案或接入备案核对
- 上线后的公安联网备案核对

## 7. 资源使用约束

服务器只有 2 核 CPU 和 4 GB 内存，开发与部署应保持克制：

- 不安装不必要的常驻服务
- 不同时运行两套 Node.js SSR 服务
- Node.js 仅用于构建前端，构建完成后不作为线上常驻进程
- 前端静态资源由 Nginx 提供
- Gunicorn worker 数量按实际内存和负载设置，不盲目增加
- PostgreSQL 为两个项目和系统保留足够内存
- 图片上传时限制文件大小和像素，并生成适合列表展示的缩略图
- 带哈希的 JS/CSS 使用长期缓存，入口 HTML 保持可及时更新
- 定期检查磁盘、数据库、媒体文件、日志和备份增长

如果两个网站同时构建、批量处理图片或执行升级，应观察内存和 Swap，避免在访问高峰同时执行高消耗任务。

## 8. 备份与迁移要求

巧侬必须独立备份和恢复，至少包括：

- PostgreSQL 数据库备份
- 媒体目录备份
- 生产环境配置的安全离线留存
- 当前部署提交号和依赖锁文件
- 恢复步骤文档

备份文件不得与婵泉混放或使用相同文件名覆盖。恢复演练需要证明巧侬可以在不读取婵泉数据的情况下独立恢复。

未来迁移到其他服务器时，应能够按以下边界整体迁移：

```text
巧侬代码 + 巧侬数据库 + 巧侬媒体 + 巧侬环境变量 + 巧侬服务配置
```

迁移过程中不应要求复制婵泉代码、数据库或媒体目录。

## 9. 当前状态

巧侬生产数据库、运行目录、虚拟环境、Gunicorn/systemd 服务、Nginx 站点、正式域名和证书均已创建并运行。安全 CD 已安装并通过首次真实部署及后续自动部署验收。

后续应持续核对资源预算、日志、磁盘、媒体和备份增长，并保持本文规定的项目隔离边界。当前精确部署状态见 `docs/当前进度与下一步.md` 和 `docs/CD方案与接入说明.md`。
