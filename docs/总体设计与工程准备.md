# 巧侬总体设计与工程准备

## 阶段说明

本文对应八阶段开发流程中的第 4 阶段“总体设计和工程准备”，内容按用户确认结果逐项补充。

## 已确认技术路线

项目采用前后端分离结构：

- 公开前端：Vue 3 + Vite。
- 管理员后台：独立的 Vue 3 + Vite 应用。
- 后端：Django + Django REST Framework。
- 数据库：PostgreSQL。
- 图片：由后端管理上传信息，文件保存在巧侬独立媒体目录。
- 生产服务：Nginx、Gunicorn、systemd 和 Certbot。

第一版不采用 Wagtail，也不使用 Django Admin 作为交付给管理员的主要后台界面；不提供草稿预览、审核发布和额外 SEO 管理流程。

## 项目目录边界

```text
qiaonong/
├── frontend/        # 公开 Vue 前端
├── admin-frontend/  # Vue 管理员后台
├── backend/         # Django/DRF 后端
├── deploy/          # 巧侬独立部署配置模板
├── docs/            # 项目文档
├── migration/       # 旧站公开迁移输入与清单
```

## 第一版模块及职责

### `core`

- 提供健康检查。
- 处理管理员登录、退出和会话状态。
- 提供各业务模块共同使用的少量基础能力。
- 不承载产品或页面内容数据。

### `content`

- 拥有首页展示内容。
- 拥有品牌介绍。
- 拥有联系方式。
- 拥有确认保留的政策页内容。

### `catalog`

- 拥有产品分类和层级关系。
- 拥有产品、产品图片、排序和上下架状态。
- 提供公开产品列表、详情和站内搜索。
- 提供管理员维护分类与产品所需的管理接口。

### 产品分类边界

- 产品分类数据及产品与分类的关系统一由 `catalog` 模块拥有。
- 分类采用最多两级的树形结构：一级分类可以包含二级分类，二级分类不能继续创建下级分类。
- 产品可以归属一级或二级分类，不强制只能归属叶子分类，以兼容“医美产品”等直接包含产品的旧站栏目。
- 一级分类停用后，其下级分类和关联产品均不在公开网站显示；后台仍保留并允许维护这些数据。
- 分类存在子分类或关联产品时禁止直接删除，应先移动或处理关联内容，避免误删产品。
- 分类需要支持名称、稳定页面地址、简介、栏目图、排序和启停状态；具体字段约束在进入 `catalog` 模块开发时逐项确认。
- 旧站栏目数字 ID 仅作为迁移追踪标识保留，新版公开 URL 不继续使用 PHP 查询参数结构。
- 公开 API 只返回公开可见的分类和产品；管理 API 可以读取和维护全部状态。

### Vue 应用边界

- `frontend/` 只调用公开只读 API，不包含管理功能。
- `admin-frontend/` 登录后调用管理 API，不承担公开页面展示。
- 两个 Vue 应用均不直接访问数据库或媒体文件系统。

## 管理后台认证与访问边界

- 管理后台采用 Django Session Cookie 和 CSRF 保护，不使用 JWT。
- 生产环境与公开官网同域部署，管理后台路径为 `/manage/`，管理 API 前缀为 `/api/admin/`。
- 管理前端启动时通过 `GET /api/admin/auth/me/` 恢复登录状态并取得 CSRF Cookie。
- 登录和退出接口分别为 `POST /api/admin/auth/login/` 与 `POST /api/admin/auth/logout/`。
- 只有处于启用状态且具有后台权限的 Django 管理员账号可以登录。
- 第一版不提供注册、忘记密码、修改密码或账号管理页面；账号创建和密码重置由项目维护者通过 Django 管理命令完成。
- 管理写操作必须同时通过登录权限和 CSRF 校验；公开前端不得调用管理接口。

以上认证组织方式参考婵泉项目中已经验证的工程经验，但巧侬使用独立账号、Session、CSRF 配置、数据库和生产环境变量，不复用婵泉的任何认证数据或配置。
