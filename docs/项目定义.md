# 巧侬项目定义

## 当前确认内容

### 项目目标

将现有巧侬官网进行等价重建，在不主动扩展业务范围的前提下完成技术升级，并部署到巧侬自有服务器。

### 项目解决的问题

- 旧站 HTTPS 异常，不能提供可靠的安全访问。
- 旧站缺少可靠的手机端响应式布局。
- 旧站页面结构、内容维护方式和技术实现需要升级。
- 新站需要脱离旧服务，部署到巧侬独立控制的服务器和运行环境。

### 目标用户

- 公开访客：浏览巧侬品牌与产品资料，并通过页面公布的联系方式联系。
- 网站管理员：通过简单管理员后台维护网站内容。

项目不设置经销商、内部员工或其他独立用户角色，权限和使用流程保持简单。

### 用户当前如何解决需求

- 公开访客通过旧网站浏览产品分类和产品详情，需要进一步沟通时拨打网站公布的客服电话。
- 网站管理员通过旧站原有管理系统维护网站内容。

### 项目核心价值

在不改变现有业务方式的前提下，用更安全、适配手机、便于维护且自主可控的新系统替代旧站，并尽可能保持访客熟悉的页面和浏览体验。

### 成功标准

- 新站能够在巧侬自有服务器上稳定运行。
- 桌面端尽可能还原旧站的视觉、内容和浏览路径。
- 手机端可以正常浏览，不出现旧站的固定宽度和横向溢出问题。
- 访客可以完整查看确认迁移的产品内容和联系方式。
- 网站管理员可以通过简单管理员后台维护确认需要动态管理的内容。
- HTTPS、备份和基本安全检查达到上线要求。

### 已知但暂不展开的约束

- 产品和页面图片可能较多，需要在第 3 阶段结合图片数量、单图大小、访问量和服务器网络条件评估流量及带宽风险。
- 图片存储、压缩、缓存、CDN 等具体方案留到第 4 阶段总体设计时确定。

### 前端还原原则

- 以旧站公开页面为视觉、内容和交互基准，尽可能保持一致。
- 不主动新增页面、栏目、业务功能或内容模块。
- 不因为常见企业站做法而增加新闻、留言、会员、购买、询盘等旧站没有的功能。
- 技术升级所必需的安全、响应式、兼容性和可维护性调整可以实施，但应尽量避免改变旧站的品牌表达和使用路径。
- 旧站中的错误、空内容、模板残留以及不属于巧侬的主体、备案和品牌信息不视为还原目标，必须单独核验。

### 部署与隔离边界

- 新站部署到巧侬自有服务器。
- 巧侬与婵泉不共用代码仓库、后台、数据库、环境变量、媒体目录、部署服务或备份。
- 第一版包含公开前端、后端和简单管理员后台。
- 不采用 Wagtail，不需要内容预览与发布工作流，也不额外开发 SEO 管理功能。

### 项目不负责的范围

- 在线购买、支付和订单。
- 会员、经销商及员工系统。
- 在线留言或询盘。
- 新闻、招聘、门店等旧站没有的栏目。
- 对接第三方业务系统。
- 原样复制旧站错误内容、空政策页和模板残留。
- 迁移或复用婵泉的品牌、数据、账号及生产配置。
